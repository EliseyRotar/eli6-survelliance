## 🎯 The right URL (H.264 video)

**`https://195.196.36.242/axis-cgi/media.cgi?container=matroska&videocodec=h264&resolution=640x480`**

This returns **H.264 video in Matroska container** — the same format the AXIS web UI uses, but you can play it in any tool.

## Why the web UI is smoother

The web UI at `/camera/index.html#/video` uses **`/axis-cgi/media.cgi`** which streams **H.264 video** (avc1.640029 codec in Matroska container). Compared to `/axis-cgi/mjpg/video.cgi` which streams **MJPEG**:

| Endpoint | Codec | Container | Quality | Smoothness |
|---|---|---|---|---|
| `https://195.196.36.242/axis-cgi/media.cgi` | **H.264** (avc1.640029) | **Matroska (.mkv)** | Higher, better compression | **Smooth, fluid, real-time** |
| `https://195.196.36.242/axis-cgi/mjpg/video.cgi` | MJPEG | multipart/x-mixed-replace | Lower, large frames | ~1 fps at 5MP, choppy |

H.264 uses inter-frame compression (only stores differences between frames), so:
- Much smaller data per frame
- Real-time framerate (25+ fps)
- Less bandwidth

MJPEG stores each frame as a complete JPEG (~543KB per frame at 5MP), limiting framerate.

## How to play the H.264 stream

### Browser (Chrome/Edge)
Paste this in the address bar:
```
https://195.196.36.242/axis-cgi/media.cgi?container=matroska&videocodec=h264&resolution=640x480
```
Chrome will warn about cert mismatch — type `thisisunsafe`. The browser will then play the Matroska H.264 stream natively.

**OR** open `https://195.196.36.242/camera/index.html#/video` and use the built-in player.

### VLC
```
vlc "https://195.196.36.242/axis-cgi/media.cgi?container=matroska&videocodec=h264&resolution=640x480"
```
VLC handles the cert mismatch with `--ignore-cert`.

### ffplay (best quality)
```
ffplay -user_agent "Mozilla/5.0" "https://195.196.36.242/axis-cgi/media.cgi?container=matroska&videocodec=h264&resolution=640x480"
```

### ffplay (HTTPS, insecure)

### ffmpeg (record to file)

## Detection methodology

```bash
# 1. Initial probe
curl -Ik "https://195.196.36.242/axis-cgi/mjpg/video.cgi"
# -> HTTP 200, Content-Type: multipart/x-mixed-replace (MJPEG)
# This was the original finding, but slow because full-JPEG-per-frame

# 2. Discover AXIS VAPIX endpoints
curl -k -X POST -H "Content-Type: application/json" \
  -d '{"apiVersion":"1.0","method":"getApiList"}' \
  "https://195.196.36.242/axis-cgi/apidiscovery.cgi"
# -> Returns 56 services including [media-cgi] and [rtsp-over-websocket]

# 3. Look up Media Stream over HTTP docs (axis developer docs):
# https://developer.axis.com/vapix/network-video/media-stream-over-http/
# Endpoint: /axis-cgi/media.cgi
# Returns H.264 (avc1.640029) in Matroska container

# 4. Test the modern endpoint
curl -Ik "https://195.196.36.242/axis-cgi/media.cgi?container=matroska&videocodec=h264&resolution=640x480"
# -> HTTP 200, Content-Type: video/x-matroska; codecs="avc1.640029"

# 5. Verify with longer stream
curl -k --max-time 10 -A "Mozilla/5.0" -o /tmp/stream.mkv \
  "https://195.196.36.242/axis-cgi/media.cgi?container=matroska&videocodec=h264&resolution=640x480"
# -> ~19KB/s real H.264 stream (vs MJPEG's 600KB/s for choppier video)
```

## Stream resource limits

The camera has a **concurrent stream limit**. After my repeated tests, I got **503 "Not enough resources available to open new stream"** responses on media.cgi and the MJPEG endpoint. The web UI on `/camera/index.html` uses one stream slot.

- Wait 60-120 seconds for slots to release
- Or use lower resolutions (160x120, 320x240) which seem to use fewer resources

The camera exposes **TWO live stream endpoints**:

1. **`/axis-cgi/mjpg/video.cgi`** — Legacy MJPEG stream. Slow (~1.25 fps at 5MP) but always works.

For the **best experience**, use the **media.cgi H.264 URL** in VLC or ffplay. The web UI at `https://195.196.36.242/camera/index.html#/video` is just a nice frontend that calls this same endpoint internally.

The smooth video you saw in the web UI is **not MJPEG** — it's **H.264 over HTTP** through `/axis-cgi/media.cgi`, which is AXIS's official Media Stream API (VAPIX Media-CGI v1.0).
